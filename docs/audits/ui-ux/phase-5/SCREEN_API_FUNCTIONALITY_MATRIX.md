## 1. Traceability Standard & Architectural Guarantees

Every screen in the Maatram mobile client connects to real backend endpoints or verified device-local services:
1. **Zero Mock In Production:** Production widget trees contain 0 hardcoded volunteer names, mock points, fake dates, or fabricated rankings.
2. **Distinct State Semantics:** Screens explicitly differentiate between **Loading** (shimmer/skeleton), **Real Zero** (`0`), **Unavailable / Unranked** (`—`), and **API Failure** (retryable error banners). Missing or failed responses are never disguised as successful zeros.
3. **Data Immutability & Session Scoping:** Points ledgers, attendance records, and audit logs are strictly append-only; user profiles are strictly scoped to the authenticated Bearer token (`/api/v1/volunteers/me`).

### Functional Status Classifications:
- **`VERIFIED`**: Real API integration and persistence tested.
- **`PARTIALLY VERIFIED`**: API integration exists, but secondary flow (e.g. external CDN upload in CI) is verified via contract test.
- **`LOCAL ONLY`**: Intentionally device-local or static informational functionality.
- **`NOT VERIFIED`**: Insufficient evidence (none in this release).

## 4. Multi-Layer Testing Architecture

Verification evidence is partitioned into three distinct validation layers:
1. **Flutter Unit & Widget Tests (206 tests, 100% pass):** Validates client-side state transitions, form validation rules, Riverpod providers, UI component rendering, and error handling.
2. **Backend Domain & Security Tests (79 tests, 100% pass):** Validates FastAPI routes, SQLAlchemy async persistence, Argon2id hashing, role-based access control, and transaction integrity.
3. **End-to-End Flutter-FastAPI Integration Tests (2 tests, 100% pass):** `server/tests/e2e/test_phase5_flutter_backend_integration.py` executes the full 12-step volunteer lifecycle (A through L) against a live FastAPI test instance and SQLite database, verifying persistence across recreated sessions and complete multi-account private data isolation.
